Lab 2 - JSON: user profiles

The task. Create a JSON document called userProfiles.json holding at least three user profiles. Each profile has a first name, last name, email address, date of birth and a preferences object with the theme, language and notification settings. Every profile also needs an address, and the preferences need a newsletter subscription setting. The document is then fetched and displayed on a page.

Step 1 - the JSON document

The file holds five profiles in an array, which is the profile section the lab refers to. Everything in it is built from the three data structures of the JSON data model: an object (the root, and each profile), an array (the list of profiles) and the name/value pairs inside them. The values cover the string, number and boolean types, and the address and preferences objects are nested inside each profile, so a profile holds objects of its own.

As the JSON data model lecture points out, a value is what it looks like: text in quotation marks is a string, a number appears without quotes, and true and false are booleans that are never quoted. JSON has no comments either, so the document explains itself through the names of its fields. 

{
  "profiles": [
    {
      "id": 3,
      "firstName": "Liam",
      "lastName": "O'Connor",
      "email": "liam.oconnor@example.com",
      "dateOfBirth": "1995-03-28",
      "address": {
        "street": "8 Colombo Street",
        "city": "Christchurch",
        "state": "Canterbury",
        "zipCode": "8011"
      },
      "preferences": {
        "theme": "system",
        "language": "en-NZ",
        "notifications": false,
        "subscription": true
      }
    }
  ]
}

Checking the structure. userProfiles.schema.json is a JSON Schema for this document. A lint tool only checks that the JSON is syntactically valid - that the braces, commas and quotation marks balance - but a schema goes deeper and checks meaning: that every profile really has all seven fields, that the email address matches an email pattern, that the date of birth is written as yyyy-mm-dd, that a postcode is four digits, and that the theme is one of the values the page knows how to display. That is the difference the JSON Schema lecture draws between syntactic and semantic validation.

Step 2 - fetching and parsing the JSON

The fetch chain below is the pattern from the Asynchronous JavaScript lecture. The first handler checks response.ok and throws when the server answered with an error, so that one catch() deals with both a missing file and a network problem. On success response.json() deserialises the text into real JavaScript objects and arrays, which is what makes profile.preferences.theme possible on the next line. 

fetch('userProfiles.json')
  .then(response => {
    if (!response.ok)
      throw new Error('Fetch error: ' + response.status);
    else
      return response.json();
  })
  .then(json => { ... })   // json.profiles is now an array of objects
  .catch(err => console.error('Fetch error: ' + err.message));
