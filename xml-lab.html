Lab 1 - XML: a book catalogue

The task. Create an XML document called book.xml in which each book has an id attribute and the child elements title, author and price. Check that the document is well formed, then fetch it from a web page with the fetch API, parse it with DOMParser and display each book's title, author and price.

Step 1 - the XML document

The catalogue has one root element, catalogue, holding eight book elements. Everything the Introduction to XML lecture listed as a rule is followed: the file starts with the XML declaration, there is exactly one root element, every element that is opened is closed, the elements are properly nested, the tag names are spelled with matching case, and every attribute value is inside quotation marks.

Each book carries the id attribute the lab asks for. The id is a reference number rather than information about the book itself, so it belongs in an attribute, while the title, author and price describe the book and are therefore child elements. The currency attribute on the price is the other case: it is the unit the number is measured in, which is the kind of meta information the lecture says an attribute should carry. The year and genre elements are extra children that show the document can be extended without disturbing the rest of it.

One title contains an ampersand. A bare ampersand would end the text there and break the document, so it is written as the pre-defined entity &amp;. There is also a comment in the file, written the same way as an HTML comment, explaining that entity. 

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE catalogue SYSTEM "book.dtd">

<catalogue xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
           xsi:noNamespaceSchemaLocation="book.xsd">
   <book id="bk105">
      <title>Harry Potter &amp; the Philosopher's Stone</title>
      <author>J. K. Rowling</author>
      <year>1997</year>
      <genre>Fantasy</genre>
      <price currency="NZD">25.99</price>
   </book>
   ...
</catalogue>

Two constraint models. The DOCTYPE line points at book.dtd, the DTD written from the XML DTDs lecture, and xsi:noNamespaceSchemaLocation points at book.xsd, the XML Schema of the same rules written from the XML Schema lecture. A parser that reads neither of them still handles the document, because being well formed and being valid are two different questions.

Step 2 - fetching and parsing the XML

fetch("book.xml") returns a promise. The first then() handler receives a response object and checks response.ok before going on, as the Asynchronous JavaScript lecture shows; response.text() then hands the second handler the contents of the file as a plain string. The lab's own two lines turn that string into a document tree, and the tree is read with the same DOM methods that would be used on an HTML page. 

const parser = new DOMParser();
const xmlDoc = parser.parseFromString(xmlText, "text/xml");

const books = xmlDoc.getElementsByTagName("book");
const title = books[0].getElementsByTagName("title")[0].textContent;

If the XML were broken, parseFromString() would return a document holding a parsererror element instead of a catalogue, so the page checks for that and reports the problem rather than drawing an empty table. The tag names used here are all in lower case to match the document, because XML is case sensitive and Title would find nothing.
